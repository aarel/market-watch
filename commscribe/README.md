# commscribe

Portable, document-driven runtime for auditable Codex execution workflows.

## Identity

Commscribe provides a deterministic request lifecycle with JSON as the canonical state authority and Markdown as the human-auditable rendered view.

Markdown navigation format:
- `communicate.md` includes an auto-generated `## Request Index` section (`REQUEST_INDEX_START/END` markers).
- Each REQ block includes a stable anchor `<a id="REQ-..."></a>`.
- Index entries use `[REQ-...](#REQ-...) — STATUS — <summary>` and are regenerated by `communicate_scan.py`.

## What You Get

- `communicate.json` canonical state store.
- `communicate.md` synchronized queue/transcript view.
- `failure_log.json` append-only structural failure audit log.
- `scripts/communicate_scan.py` deterministic state authority.
- `scripts/communicate_orchestrator.py` thin convenience orchestrator (no state logic).
- `scripts/start_communicate_ui.py` optional local web UI.
- `tests/` for transitions, immutability, and concurrency behavior.

## State Machine Contract

Allowed transitions only:

- `NEW -> ACKED`
- `ACKED -> IN_PROGRESS | DONE | BLOCKED`
- `IN_PROGRESS -> DONE | BLOCKED`

Invariants:

- `DONE` and `BLOCKED` are terminal and immutable.
- Every mutation requires explicit `request_id`.
- Timestamps are monotonic (`last_updated_at >= created_at`, monotonic updates).
- Illegal transitions fail closed.
- Parse/schema errors fail closed with repair guidance.
- Structural failures persist durable `SYSTEM_BLOCKED` events in `failure_log.json`.
- Lock contention aborts safely with retry guidance.

## Core Workflow

1. User writes request in INPUT PAD in `commscribe/communicate.md`.
2. Core authority consumes input and creates `NEW` request:

```bash
python3 commscribe/scripts/communicate_scan.py consume
```

3. Codex mutates lifecycle through explicit commands:

```bash
python3 commscribe/scripts/communicate_scan.py ack --id <REQUEST_ID> --plan "..."
python3 commscribe/scripts/communicate_scan.py log --id <REQUEST_ID> --message "..."
python3 commscribe/scripts/communicate_scan.py complete --id <REQUEST_ID> --result "..." --evidence "..."
# or
python3 commscribe/scripts/communicate_scan.py block --id <REQUEST_ID> --reason "..." --next-steps "..."
```

## Command Words

- Use `communicate>` as the command-word trigger for Codex lifecycle execution.
- `communicate>` is a protocol trigger and may map to `python3 commscribe/scripts/communicate_scan.py` commands, not a shell binary named `communicate`.
- Authoritative `communicate>` behavior is defined in `commscribe/CODEX_COMMUNICATE_INSTRUCTIONS.md`.

## Orchestrator Boundary

- Orchestrator (`communicate_orchestrator.py`) may call core CLI transitions.
- Orchestrator must not read/write canonical state directly.
- All enforcement remains in `communicate_scan.py`.
- Orchestrator checks `system-status` and refuses execution while `SYSTEM_BLOCKED` is active.

## Failure Recovery Protocol

1. On structural failure, runtime exits non-zero and appends `SYSTEM_BLOCKED` event to `failure_log.json`.
   This check is enforced on all entrypaths, including empty-input consume no-op paths.
2. Failure artifacts include source-aware metadata:
   - `failure_scope`: `STRUCTURAL_JSON_FAILURE` or `STRUCTURAL_MARKDOWN_FAILURE`
   - `source_file` + `source_hash` for the file that caused the block
3. Corrupted source file is left unchanged. No auto-repair is attempted.
4. Re-running without repair does not append duplicate `SYSTEM_BLOCKED` for the same `source_file` + `source_hash`.
5. After manual repair, run:

```bash
python3 commscribe/scripts/communicate_scan.py system-status
```

6. Successful validation appends `SYSTEM_RECOVERED` event and normal lifecycle resumes.
   Recovery is source-aware: markdown-origin failures clear after markdown repair only, without requiring JSON mutation.

## Optional Local UI

```bash
python3 commscribe/scripts/start_communicate_ui.py
```

Then open `http://127.0.0.1:8765`.

UI write path guarantees:
- UI input writes are routed through `communicate_scan.py set-input` (scanner API), not direct markdown rewrites.
- UI and scanner share the same lock contract to prevent queue/index clobber under concurrent activity.
- Deep-link scheme for request detail navigation:
  - Query: `http://127.0.0.1:8765/communicate?req=REQ-YYYYMMDD-HHMMSS`
  - Hash: `http://127.0.0.1:8765/#/REQ-YYYYMMDD-HHMMSS`
  - REQ IDs in the list are rendered as standards-compliant links and can be copied as shareable URLs.
- Runtime-contained theme files:
  - `commscribe/ui/theme.css` (portable default)
  - `commscribe/ui/market-watch-theme.css` (optional overlay)
  - no host-project CSS imports or CDN dependencies
